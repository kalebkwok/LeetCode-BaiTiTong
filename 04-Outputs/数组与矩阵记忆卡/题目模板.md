# 通用 LeetCode 复习记录

一题一份记录，主卡、追问和默写从同一份记录取内容。Python 题解来源保留为原始 Markdown。

| 字段 | 填写要求 |
|---|---|
| `uid` / `id` | 稳定标识，例如 `lc-238` / `238`。进度与此绑定，改标题不能改 UID。 |
| `title` / `level` / `group` | 题名、难度、专题内分组。分组应表达共同思路。 |
| `source` | 原题解的仓库相对路径。 |
| `prompt` | 不泄露解法的短题干；保留影响算法选择的条件。 |
| `example` | 一组能手推的小输入与输出；不要只选最简单的无分支情况。 |
| `recognition` | 哪些条件提示此方法？不要只写算法名称。 |
| `mnemonic` | 一句简短记忆线索；必须能由后面的解释推出。 |
| `why` | 为什么这个方法正确？尽量给出因果解释。 |
| `invariant` | 关键变量、递归契约、栈 / 堆内容或 DP 状态在什么时刻表示什么。 |
| `hint` | 一层启发性问题，仍让学习者有推理空间。后续提示使用识别线索和步骤。 |
| `steps` | 3–5 个可以重建代码的步骤，包含初始化、更新、终止。 |
| `trace` | 对小输入逐步记录关键状态，与代码保持一致。 |
| `trap` | 一个具体错误，加上能使错误写法露馅的输入。 |
| `complexity` | 时间 / 空间及变量含义；明确是否计入输出，以及语言实现的额外分配。 |
| `prerequisites` | 概念 ID 列表，每个概念有短解释和例子。 |
| `related` | `{id, kind, why}` 列表。`kind` 表明同模板、条件变化、易混淆等关系，`why` 解释方法为什么相同或不同。可跨专题。 |
| `followup` | `type` 为 explain / trace / transfer；包含独立的小问题 `prompt` 与 `answer`。 |
| `codeBlock` | 可选的零起始 Python 代码块下标。选择完整实现，避开讲解中的局部片段。 |
| `traceLabel` | 可选。逐步状态称“手推一遍例子”；例子与边界问题称“例子与边界推演”。 |
| `codeOverride` / `codeNote` | 可选。仅在原始题解代码需教学调整时使用，并说明原因。 |

## 示例：238 的追问

**题目：** 为什么必须先写入左侧乘积，再把当前元素乘进去？如果有两个零会怎样？

**参考回答：** 提前更新会把自己算进乘积。两个零时，排除任意一个位置仍包含至少一个零，因此全部答案为零。

这张追问检查的是不变量和边界推理，不需要再次背整段代码。

## 不同题型如何填写不变量

- 双指针：两个指针之间 / 之外已经满足什么？移动哪一个有依据？
- 树与递归：函数对当前节点返回什么？父节点依赖哪些子结果？
- 动态规划：状态的每个下标是什么意思？更新顺序会不会读到当前轮的新值？
- 图：访问标记何时写？队列 / 栈里是哪一类待处理节点？
- 堆 / 单调栈：容器保存什么、按什么顺序、什么时候失效或弹出？
- 贪心：本次选择为什么不会让剩余问题更差？

## 内容发布前检查

1. 主卡没有提前显示算法名或不变量答案。
2. 一句口诀、解释、代码和手推示例互相一致。
3. 追问能暴露误解，不只是换句话重复题名。
4. 相关题写清联系原因，避免仅因同属一个标签就推荐。
5. 普通例子与一个边界例子都通过参考解法。
6. 只新增内容不会改掉已有题目的 UID 或复习历史。

## 专题共用同一个页面

在 `topics.json` 中为专题填写 `connectionRule`：说明本专题用什么问题串联各题。`groups` 每组有 `id`、`title`、`description`；概念文件里的例子帮助解释这个分组。

同一题只在一个主专题定义，其他专题通过 `related` 链接它。不要为跨专题复用创建第二个 UID。地图搜索覆盖所有专题，打开关联题会自动切换所属专题，保存记录仍以该题 UID 为准。

题干必须独立可读，特别保留允许重复、方向、值域、时间顺序和输出目标等条件。正面例子只显示输入与输出；详细执行步骤放到答案后的 trace。若原笔记只留了简短提示，需要补齐题干，不能直接当作完整卡片。
