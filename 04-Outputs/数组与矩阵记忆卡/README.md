# 拾忆 · 本地算法复习

177 道题、12 个专题，共用“回忆 → 解释 → 追问 → 默写”的学习模板。题目按各专题的关键决策连接，支持跨专题搜索和对比。

现在由 React + TypeScript 页面、FastAPI/Uvicorn 本地服务和 SQLite 数据库保存学习数据。同一服务下的 Chrome、Codex 内置浏览器等读取同一份进度，不需要账号或云端服务。

## 打开与继续学习

在 Finder 中双击 **打开记忆卡.command**，打开 [拾忆](http://127.0.0.1:8765/)。保留启动窗口；关闭窗口会停止服务，已提交的数据仍在。再次双击即可继续。

首次准备使用 macOS / Linux、Python **3.13.12** 和 Node **24.19.0**（版本文件与 CI 一致）。在本目录执行：

```sh
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
npm ci --prefix frontend
npm run build --prefix frontend
```

之后日常双击只启动 `.venv` 中的 Python，使用一个 Uvicorn worker；不联网安装，不启动 Node/Vite，也不重新打包。缺环境或构建时启动器会给准备提示。不要直接打开构建后的 HTML，它需要同源 API。

首次从旧版升级时，先关闭旧启动窗口，再重新启动。打开原来使用的浏览器，新版会自动将它的旧进度合并到数据库。多个浏览器可分别迁入；按时间保留较新数据，旧的 localStorage 原文不删除。旧版只有累计记录，没有逐次事件，因此不会编造迁移前的学习历史。

## 每天的使用流程

1. **学习中心**默认打开总览，查看累计刷题数、今天完成的题数、到期题、最近 7 天学习量及专题进度。点击统计、日期或专题可进入对应记录。
2. **今日复习 / 复习看板**分为待复习、今日新题和今日已完成。到期旧题覆盖所有专题；新题从当前专题开始。点卡片进入统一复习模板。
3. 看题后先口述或写思路，再核对答案。提示逐层展开；认出方法、讲清原因、独立写出分别自评。
4. 写一个下次想检查的卡点。思路草稿、追问草稿、默写代码按题目和练习类型分别自动保存；刷新后仍可继续。
5. **记忆地图**按专题思路分组，可搜索全部题库。点“关联”比较条件和方法，点“继续默写”接着写已有草稿。
6. **刷题记录**每道题一行，显示首次学习、最近提交、有效提交次数和下次复习。支持题号 / 标题搜索、专题、状态、提交日期筛选和排序；每页 20 题。点击题目查看精确到秒的提交时间线，按每页 50 次加载更早记录。
7. **单题时间线**保留计划复习、自由练习、追问与默写的评分、提示使用和当次安排的下次复习时间。只允许撤销仍可回退的记录；撤销保留卡点、草稿和事件标记，统计自动更新。

网页提供自评与参考答案，不会执行用户输入的代码。默写完成后可复制到自己的编辑器或 LeetCode 运行。

## 休闲模式与疯狂模式

左侧和“数据与设置”均可一键切换：

- **休闲模式**：每天最多引入 3 道新题。
- **疯狂模式**：每天最多引入 20 道新题。

额度在全部专题、同一服务的浏览器之间共享，切换后立即保存到 SQLite。切换不重置当天已引入的数量：疯狂模式已学 8 道后切回休闲模式，当天剩余新题为 0。第二天按当前选择的模式重新计算。旧题复习和自由练习不占新题额度，后者继续遵循原有不改复习日期的规则。当前专题不足剩余额度时，可以切换专题继续。

旧备份中的自定义额度继续保留并明确标注为旧设置；选择任一模式即可切换到 3 或 20。新数据库默认休闲模式；已有设置以 SQLite 为准。

## 总览与记录的统计口径

- “累计刷过”按题目去重，包含计划复习和有评分的自由练习；只写草稿不算刷过。
- 每题每天在“今日已完成”和七日图表中计 1 题；每次成功保存的有效提交另计次数。当天既有计划复习又有自由练习，同题优先归入计划复习；新题以首次进入计划的日期区分。
- “已完成”表示提交过自评，不等同于掌握。没想起的题在 10 分钟后重新进入待复习，已完成栏仍保留今天的提交。
- 撤销记录不计入有效统计，但可在单题时间线查看撤销标记。仅有撤销记录的题可在“记录已撤销”筛选中找到。
- 日期筛选匹配范围内的任意一次有效提交，不仅匹配最近提交。所有浏览器按服务端配置的共享学习时区显示，首次学习使用最早留存时间。
- 旧版只有累计次数的题，显示“另有旧版累计 N 次”；不会生成不存在的逐次提交，也不会将旧累计次数补入七日图表。

## 数据在哪里

所有路径相对于本文件所在目录：

| 文件或目录 | 内容 |
|---|---|
| `data/review.sqlite3` | 学习进度、三项能力、卡点、各类草稿、设置、逐次学习历史、迁移与请求记录 |
| `data/backups/` | 自动、手动、导入前及恢复前的完整 SQLite 备份 |
| `data/recovery/` | 使用离线恢复工具时保留的原数据库文件 |
| `content.json` / `concepts.json` | 03 数组与矩阵的卡片与概念 |
| `decks/` | 其他专题的同格式卡片与概念 |
| `topics.json` | 专题配置、分组和连接原则 |
| `frontend/public/content/` | 自动生成 JSON 题库与题解快照 |
| `frontend/dist/` | 唯一页面构建输出，含 `/content/notes/lc-N.html` |

原始题解仍在仓库的 `02-Wiki/题目详解/`，数据库升级不会修改它们。学习数据目录已被 Git 忽略，代码更新不会把私人学习记录提交到仓库。

浏览器 localStorage 仅用于暂存未提交请求和保留旧版迁移来源。成功保存的权威数据在 SQLite。界面明确区分“正在保存”“已保存”和“未连接”；只有收到数据库提交确认才显示已保存。

## 保存失败与多浏览器使用

- 本地服务断开时，未提交内容进入浏览器的待保存队列；恢复后自动重试，也可以点“重新连接 / 重试保存”。
- 每次操作有固定请求编号，即使数据库已提交但网络响应丢失，重试也不会重复计入。
- 数据库用事务顺序处理评分，不会用某个浏览器的整份旧状态覆盖其他浏览器的新进度。
- 两个页面同时编辑同一份卡点或草稿时，发生版本冲突会展示两份内容，允许选择保留哪份或先导出。不会静默覆盖。
- 未提交内容还在浏览器时，不要清除该浏览器的数据；可以导出待保存内容，之后通过“导入 JSON”重新提交。如果浏览器本身拒绝暂存，界面会提示内容仅在本页，此时应保持页面打开。
- 页面每 15 秒及重新获得焦点时同步数据库。阅读中的卡片不会突然切换；再进入对应页面可查看更新后的内容。

## 备份与恢复

**自动备份**在启动、正常退出，以及距上次备份至少 15 分钟后发生保存时创建。导入与恢复之前强制备份。最多保留 30 份，每份使用 SQLite 的在线备份接口生成并检查完整性。

在“数据与设置”可以：

- 查看实际数据库路径和备份列表；
- 立即创建完整数据库备份；
- 选择一个备份恢复到对应时间点。恢复前会再备份当前数据；其他页面恢复前的待保存请求会要求单独确认。

“导出已提交记录 JSON”生成包含进度、卡点、草稿、设置和学习历史的 JSON 文件，便于另存到外部磁盘或迁移到另一台电脑。“导入 JSON”支持旧版进度和新版完整备份：合并较新的记录，导入新版学习设置，不清空当前已有题目。JSON 合并不会删除当前记录；需要准确回到一个时间点时，使用 SQLite 备份恢复。

存在待提交操作时按钮明确显示“导出待保存内容”，只导出队列。重新导入会保留原请求 ID、已发送请求体和原 databaseId；不同或缺失数据库标识时必须逐项确认，绝不自动改绑重放。旧导出原文件保留用于核对。JSON 没有全部撤销快照、幂等回执和元数据，不能用作精确恢复点。

不要在服务写入时仅复制主 `.sqlite3` 文件，因为 SQLite 可能正在使用 WAL 辅助文件。使用应用内备份 / 导出，或停止服务后复制整个 `data` 文件夹。保存在同一磁盘的自动备份不能抵御整块磁盘损坏，重要进度可另存一份到外部位置。

### 数据库损坏时恢复

如果无法打开网页，启动程序会保留原文件并提示错误。先关闭本项目的启动窗口，在本目录执行：

```sh
.venv/bin/python recover.py review-实际日期-实际编号-auto.sqlite3
```

将参数替换为 `data/backups/` 中的一份实际文件名。工具会检查备份、将原数据库和 WAL 辅助文件保留到 `data/recovery/`，再原子替换数据库。服务仍在使用该目录时，恢复工具会拒绝操作。完成后重新双击启动文件。

## 复习规则

- 没想起：10 分钟后再试同一种问法。
- 需要帮助：1 天后复习。
- 独立完成：间隔依次为 1、3、7、14、30 天，之后保持 30 天。
- 主卡的认出 / 解释两项取较弱者；核对前用过帮助则最高计为“需要帮助”。
- 成功完成后，下一轮在主卡与追问间交替；自由练习和默写只更新能力与历史，不改变计划复习日期。
- 这是固定间隔规则，当前没有自适应记忆模型。能力评分来自个人自评。

## 维护题库

一题只有一个稳定 UID，例如 `lc-238`；跨专题通过相关题号连接，不为同一题建立多份进度。模板见 `题目模板.md`。

修改 Markdown 或 JSON 后运行：

```sh
npm run build --prefix frontend
```

构建完成后刷新网页，学习数据库不受影响。`build_content.py` 是唯一内容构建实现，默认输出 JSON 到 `frontend/public/content`；兼容格式可显式指定 `--format js --output-dir 临时目录`。`codeBlock` 指定原题解中的完整 Python 实现；少量教学调整有 `codeOverride` 和说明。215 的基础堆解法与平均线性时间进阶要求、148 的递归栈与常数空间进阶要求，均在卡片中明确区分。

## 共享时区与私有手机入口

`start.py` 保留 `--no-open`、`--port`、`--data-dir`，新增 `--time-zone`、`--allow-host`、`--allow-origin`。时间点仍用 Unix 毫秒，学习日、额度和日期筛选统一使用 session 返回的 IANA 时区；10 分钟是经过时间，1/3/7/14/30 天按日历推进，包含夏令时。无效时区拒绝启动，不重写老时间戳。

为日常双击保存配置，可在应用根创建 **被 Git 忽略** 的 `launch.local.json`。它可省略；缺省数据仍是本应用 `data`，时区从主机解析。以下名称仅为示例，部署时替换为实际值：

```json
{
  "port": 8765,
  "timeZone": "America/Chicago",
  "allowedHosts": ["study.example.ts.net"],
  "allowedOrigins": ["https://study.example.ts.net"]
}
```

正式切换若从独立发布目录运行，配置 `dataDir` 为原数据目录的绝对路径；先核对路径，避免把空库当作旧进度。命令行参数覆盖端口、目录与时区；`SHIYI_TIME_ZONE` 可覆盖配置时区。地址参数追加明确的 Host/Origin，本机当前端口的 127.0.0.1 与 localhost 始终允许。

电脑和手机登录获准访问的 Tailscale 网络，访问名单在本机/管理后台限制为实际参与者。主机仍只监听 `127.0.0.1:8765`；按 [Tailscale Serve 文档](https://tailscale.com/docs/reference/tailscale-cli/serve) 用私有 HTTPS 代理，例如 `tailscale serve --bg http://127.0.0.1:8765`，使用 `tailscale serve status` 核对入口，并把实际名称填入本地配置后重启拾忆。不启用 Funnel、公网转发或通配 CORS。服务不信任浏览器提供的代理/身份头，当前 token 不是 Tailscale 访问授权。

全部参与者有相同权限，共享进度、设置、卡点、草稿和历史。电脑休眠或停服期间不可访问；只有收到提交确认的内容才显示已保存。

## 正式切换与回退

1. 在原浏览器入口处理冲突并等待发送队列清空；不能发送的内容先导出队列，同时保留旧版 localStorage 原文。
2. 使用在线 SQLite 备份，或停服后复制整个数据目录，另存到自动轮转的 30 份备份目录以外。恢复点验证前保留它。JSON 导出用于合并，不代替该恢复点。
3. 在干净发布目录安装与构建，再停旧服务，显式指向原数据目录启动新服务。新旧页面不同时作为迁移写入客户端。
4. 从旧 origin 到新端口、localhost/127.0.0.1 或 Tailscale HTTPS 都不自动搬 localStorage。新入口导入旧队列时保留原 epoch，逐项处理冲突并核对记录、草稿和历史，不清除原浏览器数据。
5. 用实际手机与主机确认同一个数据库、15 秒及重新聚焦同步、中文输入/切题、双设备冲突和共享学习日，并记录设备与结果。
6. 回退代码与恢复数据库分别处理：停服后回到兼容 schema 1 的旧版本，必要时用 SQLite 恢复点或 `recover.py` 恢复数据。关闭对应 Serve 入口可退回本机使用，不替换其他 Serve 配置。

本次实施使用隔离工作树和临时测试数据。正式数据切换与真实手机/Tailscale 验收尚未执行，桌面窄屏检查不能替代它们。
